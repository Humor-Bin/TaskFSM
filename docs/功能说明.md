# TaskFSM 功能说明

## 1. 产品定位
TaskFSM 是人类与 AI Agent 之间的任务执行控制平面。模型或 Agent 负责“如何完成”，TaskFSM 负责“谁可以做、何时做、状态能否迁移、执行是否存活、产物是否齐全、是否经过审查”。

## 2. 前端运行控制台
- 状态流水线：任务池、待办、就绪、进行中、待审查、阻塞、完成
- Agent 运行拓扑：展示 Agent、任务、依赖与服务关系
- 任务详情：运行 ID、租约、心跳、进度、依赖、事件、产物
- 实时事件流：通过 SSE 接收服务端事件后刷新运行图
- 在线/离线状态：API 不可用时明确显示离线演示模式
- 人类监督：待审查任务可在控制台批准并完成

## 3. 任务状态机
服务端维护唯一可信状态。Agent 只能调用动作接口，不能 PATCH 状态字段。

关键规则：
- ready -> in_progress：必须由能力匹配的 Agent Claim，且依赖已完成
- in_progress -> review：必须持有有效 Lease、依赖已完成、至少存在一个 Artifact
- review -> done：必须存在 approved Review 且依赖已完成
- in_progress -> done：明确禁止
- Lease 过期：运行结束，并将仍处于 in_progress 的任务回收到 ready

## 4. Agent Runtime
Agent 注册后获得一次性返回的 API Token，服务端只保存哈希。后续 discover、claim、heartbeat、progress、artifact、request-review 请求必须携带匹配的 Bearer Token。

Agent capabilities 用于筛选可领取任务。Claim 同时创建 Run 与 Lease，从而把“任务”与“某次具体执行”分离。

浏览器控制台不会持有 Agent Token，也不会代替 Agent 发起 request-review；该动作必须由持有有效 Lease 的 Agent 通过 SDK/API 发起。

## 5. Run / Lease / Heartbeat
- Task：长期业务对象
- Run：一次执行尝试
- Lease：Agent 对任务的临时执行所有权
- Heartbeat：延长 Lease 并证明 Agent 仍存活

这使 TaskFSM 能处理 Agent 崩溃、超时和重试，而不会让任务永久卡死。

## 6. Artifact / Review
Artifact 支持 file、url、git_commit、pull_request、report、json 等通用类型。Agent 提交产物后才可以请求审查。

Review 记录 reviewer、decision、reason。approved 后，人类才能将任务标记完成。

## 7. Event 与实时同步
每个关键动作写入 Event：注册、创建、领取、进度、心跳、产物、申请审查、审查决定、完成、租约过期等。

前端通过 `/api/events/stream` SSE 实时感知变化，并通过 `/api/dashboard` 获取新的聚合快照。当前单实例 Broker 支持从 FastAPI 工作线程安全发布事件；多实例阶段再切换 Redis Pub/Sub 或 NATS。

## 8. 数据库与部署
默认 SQLite，方便单机启动；生产可设置 PostgreSQL `DATABASE_URL`。当前 Event Log 与业务数据共享事务数据库。

Docker Compose 提供 PostgreSQL、TaskFSM 和预留 Redis 服务。Redis 当前未接入运行路径，作为多实例实时总线的后续基础设施。

## 9. Agent SDK
Python SDK 屏蔽 HTTP 细节。任何 Codex、Claude Code、自研 Agent 或本地脚本，只要调用统一协议即可接入，不需要 TaskFSM Core 理解具体模型实现。

当前 SDK 提供：register、heartbeat、available_tasks、claim、lease_heartbeat、progress、submit_artifact、request_review。

## 10. 安全边界
当前版本已经实现 Agent Bearer Token 校验，但尚未实现人类用户登录、OIDC、组织/项目 RBAC。人工审查与完成接口中的 reviewer/actor 仍是开发态字段；CORS 也为本地开发采用宽松配置。因此当前版本适合本地/受控网络验证核心闭环，不应在未补齐人类认证和权限控制前直接暴露到公网。

## 11. 后续演进
下一阶段建议独立规划：
- OIDC / Session / RBAC 与项目隔离
- Alembic 数据库迁移
- Redis Pub/Sub 或 NATS 实时总线
- 自动调度、Retry、SLA、Agent 负载与能力评分
- GitHub/GitLab Artifact 深度集成
- Codex、Claude Code 等具体 Agent Adapter
- 多项目、多工作区与审计策略
